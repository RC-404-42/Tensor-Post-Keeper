# 拾圖 · Tensor Post Keeper

**把喜歡的圖，完整收好。**

拾圖是一款供 Chromium 系列桌面瀏覽器使用的圖片批次收藏擴充功能，支援 Tensor.Art 與 Tensorhub.Art。無論是一篇貼文裡的多張圖片，還是作者頁中可載入的貼文，都能透過工作台批次下載，省下逐張點擊與確認存檔的麻煩。

選定一次收藏資料夾後，拾圖會記住位置，將網站原生下載按鈕提供的檔案直接寫入資料夾。圖片不經轉檔、縮放或重新壓縮，保留網站下載檔原有的尺寸、畫質與內嵌生成資訊；已完成且核對一致的圖片可以跳過，方便中斷後續抓。

**此產品由 GPT 開發，依使用者提出的需求與實際測試回饋持續調整。** 拾圖是獨立工具，非 Tensor.Art 或 Tensorhub.Art 官方產品，與上述平台無隸屬關係。

| 項目 | 說明 |
| --- | --- |
| 目前版本 | 1.2.2 |
| 支援網站 | Tensor.Art、Tensorhub.Art |
| 瀏覽器 | 桌面 Chrome、Edge 等提供資料夾寫入介面的 Chromium 瀏覽器；最低版本要求為 Chromium 116 |
| 下載範圍 | 單篇全部圖片、作者頁可載入貼文的全部圖片 |
| 存檔方式 | 選定並記憶資料夾，批次直接寫入；不需更改瀏覽器下載設定 |
| 操作介面 | 網站上的下載面板與獨立工作台分頁 |

一般使用不需要 Node、Python、Git 或其他應用程式。目前未提供 Firefox 版本。

## 更新既有安裝

1. 結束正在進行的工作，解壓縮本包。
2. 將本包內的檔案覆蓋到原本載入擴充功能的資料夾，同一層的 manifest.json 應顯示 1.2.2。
3. 到 chrome://extensions（Edge 為 edge://extensions）按「拾圖」的重新載入按鈕。
4. 關閉舊工作台，重新整理 Tensor.Art / Tensorhub.Art 分頁，再開啟工作台。面板與工作台應顯示 1.2.2。

請保留原本載入的資料夾位置；之後更新也覆蓋同一個位置並重新載入，以保留擴充功能身分與已記憶資料夾。移除擴充功能或換到新路徑重新安裝，可能清除或改變這份記憶。

## 第一次安裝

完整解壓縮至固定位置，開啟 chrome://extensions 或 edge://extensions 的「開發人員模式」，按「載入未封裝項目」，選擇直接包含 manifest.json 的資料夾。使用無痕視窗者，需允許擴充功能在無痕中執行。

主要適用桌面 Chrome / Edge，最低 Chromium 116。其他 Chromium 衍生瀏覽器若未提供 File System Access API，會顯示不支援，不會要求修改瀏覽器旗標或下載設定。

## 資料夾記憶與避免套娃

第一次選擇收藏根目錄後，程式把資料夾控制代碼保存在擴充功能自己的 IndexedDB。下次開工作台會恢復它；寫入權限仍有效時直接可用。權限失效時按「允許沿用」重新授權同一個資料夾，不需要再次開資料夾選擇視窗。

只有按「更換存檔資料夾」才會選其他位置。無痕模式的資料與授權不保證跨工作階段保留；移除擴充、清除擴充資料或移動原資料夾，也可能需要重新選擇／授權。

選定的位置就是收藏根目錄，不會無條件往下新增一層 Tensor-Post-Keeper。為相容舊版：

- 直接選到 Tensor-Post-Keeper：沿用該資料夾，不再建立同名子資料夾。
- 選到舊版的上層資料夾，而裡面已有 Tensor-Post-Keeper：自動沿用已存在的收藏目錄，方便續抓。
- 選到作者 ID 資料夾：該作者的批次不會再追加一次相同作者 ID。
- 選到含 download-index.json 的單篇貼文資料夾：提示應選外層收藏根目錄，避免把貼文資料夾當成根目錄繼續套下去。

已經形成的多層資料夾不會自動搬移、合併或刪除。程式會防止新增重複層級；你可以選定希望繼續使用的最外層收藏目錄。

## 單篇貼文

1. 在網站打開貼文圖片，看到輪播與網站原生下載按鈕。
2. 右下角按「整篇下載 → 開啟工作台」。
3. 在工作台按「選擇存檔資料夾」，挑一個圖片收藏用的資料夾，並在瀏覽器詢問時允許寫入。
4. 按「下載此篇全部圖片」。之後同篇每張都直接寫入該資料夾，不逐張跳出另存新檔。

工作台會記住選定的收藏根目錄，後續自動恢復；必要時只需再允許沿用。一般手動下載仍保留瀏覽器原本的詢問儲存設定。

第一次可按「測試資料夾寫入」，先確認選定資料夾能存檔並讀回核對。這會在 收藏根目錄／_write-test／內建立一個小型文字測試檔。

## 作者頁批次

1. 進入作者個人頁，建議先切到「貼文／Posts」。
2. 右下角按「整個作者頁 → 開啟工作台」。
3. 選擇存檔資料夾。
4. 按「掃描作者貼文」。程式會自動捲動原本的作者分頁、收集貼文，依貼文編號去重。
5. 掃描結束後檢查清單，保留要下載的貼文。清單可以全選、取消選取、翻頁。
6. 按「下載所選貼文」。程式會開一個處理分頁，依序打開每篇貼文，下載該篇全部圖片，不只抓封面。

「最多掃描 0 篇」代表持續掃描全部可載入的內容。可改成指定篇數，也可隨時「停止掃描，保留結果」。圖片總數要展開各篇後才能確定；清單顯示的「已見 N 張」只是作者頁已呈現的圖片數。

如果到頁底連續 12 秒沒有新增內容，掃描會停止。當收集篇數少於頁面標示總數，介面會明確提示可能有隱藏、篩選或載入限制。這不保證取得帳號歷史上所有內容，只處理目前可正常存取、可手動下載的圖片；不繞過私人、刪除或受限制內容。

若連續三篇無法處理，會停止並記錄原因，避免持續對網站重試。

## 儲存結構與續抓

單篇：

收藏根目錄／貼文編號／001_圖片ID_網站原始檔名.png

作者批次：

收藏根目錄／作者ID／貼文編號／001_圖片ID_網站原始檔名.png

副檔名依網站實際提供的格式保留；.png 僅為範例。同名檔案會加序號，圖片不覆蓋。

每個貼文資料夾會有 download-index.json，記錄已成功保存的圖片、檔名、位元組數與 SHA-256。預設「跳過已完成且檔案核對相同的圖片」會讀回既有檔案核對；圖片遺失或內容變動時不會誤判完成。保留這個紀錄檔，重新掃描／下載同一作者，即可跳過已完成項目。

「另外保存貼文資料 JSON」會另存網站貼文區的文字、來源與本次處理結果，不寫入圖片。它和 download-index.json 的進度紀錄不同。

## 暫停、停止與分頁

- 暫停：停止後續圖片；目前已開始的寫入會先處理完。
- 停止：停止後續工作，已完成圖片與紀錄保留。
- 中斷後續抓：重新開啟工作台、選回同一個資料夾，重新掃描並下載。已完成且核對一致的圖片會跳過。
- 下載期間保持工作台與處理分頁開啟，不要手動切換處理分頁的圖片。可以去其他分頁工作；背景分頁可能受瀏覽器降速影響。
- 停止時若網站尚未產生原檔，請先重新整理來源分頁再重試，避免遲到的原生檔案與新工作混淆。
- 同時只執行一個工作台的掃描／下載。關閉工作台會停止後續寫入；重新開啟可依磁碟紀錄續抓。

## 原始檔案與生成資訊

檔案基準是同一張圖片在網站按原生下載按鈕提供的最終檔案。本工具不使用預覽圖充數、不猜或改寫 CDN 網址、不解碼為像素、不使用 Canvas、不轉格式、不重新壓縮、不裁切，也不增刪圖片內的生成資訊。

接手路徑涵蓋原生下載連結、Blob 與網站使用的檔案儲存介面。圖片位元組分段傳送至工作台，傳送前後核對 SHA-256；寫入選定資料夾後再讀回核對。核對不符會報錯，不保存縮圖替代品。單張上限 512 MiB，超過會停止。

若網站提供最終 HTTPS 檔案網址，使用該網址原樣讀取原始檔案，之後走相同資料夾寫入與核對流程。

網站下載檔本來內嵌的 PNG parameters、EXIF 等資訊會隨檔案保留；網站原本沒內嵌的資訊無法憑空還原。若網站自己先處理了下載檔案，本工具不宣稱取得處理前的伺服器母檔。

## 診斷與已知限制

- 顯示「來源未就緒」：回到原本的網站分頁，確認已登入且作者頁／貼文可見，再按工作台的「重新連接來源」。來源分頁若已關閉，請從網站重新開啟工作台。
- 作者下載應顯示「作者貼文來源」及「掃描作者貼文」。若未顯示，重新整理網站後再連接來源；切換不同作者後需重新掃描。
- 問題持續時，可按「複製診斷」取得版本、來源與錯誤紀錄，回報前可自行檢查內容。
- 確認網站面板及工作台都標示 1.2.2，避免實際仍在執行舊版。
- 工作台能做「測試資料夾寫入」。權限失效時按「允許沿用」重新授權，不必重選資料夾，也不會退回逐檔另存流程。
- 仍有逐張另存視窗：確認只有一份拾圖啟用，停用重複載入的舊副本並重新整理網站；更新時保留原本載入路徑。下載期間不要另外點網站的下載按鈕。
- 若瀏覽器缺少資料夾選擇介面，工作台會明確報錯，請改用桌面 Chrome / Edge。
- 作者頁可能載入不完全、網站內容可能被隱藏。掃描數量會顯示，未取得的內容不會假裝已完成。
- 模型檔、影片與音訊不在本版範圍。模型範例頁（model_id）只處理目前單張。

## 權限與隱私

存檔資料夾的授權發生在擴充功能自己的工作台，不在 Tensor 網站內。目錄控制代碼保存在擴充功能自己的 IndexedDB，供下次工作台恢復，不傳給網站。

storage 保存短期工作狀態；網站及圖片 CDN 的存取權用來操作來源頁與讀取網站給出的原檔網址。本版沒有 downloads、offscreen、修改瀏覽器設定或存取全部網站的權限。不讀取帳號 Token，不傳送圖片與貼文資料到第三方，不含追蹤、遠端程式碼或外部執行套件。

## 版本紀錄

以下依版本由新到舊排列；本次僅整理說明文件，程式版本維持 1.2.2。

### 1.2.2｜作者來源辨識與連線修正

- 開啟工作台時傳遞目前頁面網址，並重新確認來源分頁的網址、版本與作者／貼文狀態。
- 修正作者模式可能落入單篇模式的問題；來源無效時直接提示，不再啟動假的貼文工作。
- 來源未就緒時停用掃描與下載，選擇或恢復資料夾不會解除來源阻擋。
- 新增「重新連接來源」，支援來源重新整理後重試；切換作者時清除舊清單。
- 支援從作者個人頁的其他分頁辨識作者，掃描時轉到該作者的 Posts 分頁。

### 1.2.1｜記憶資料夾與重複層級修正

- 記憶已選定的收藏資料夾，後續自動恢復；必要時可按「允許沿用」重新授權。
- 修正反覆建立 Tensor-Post-Keeper 或相同作者子資料夾的問題。
- 相容既有收藏根目錄與下載紀錄；選到單篇貼文資料夾時提示改選外層。

### 1.2.0｜資料夾直存與作者批次

- 改用選定資料夾直接寫入檔案，避開逐張另存流程。
- 新增工作台、作者貼文掃描、下載清單選取與逐篇展開下載。
- 新增磁碟下載紀錄、既有檔案核對續抓、同名保護及 SHA-256 完整性核對。

### 1.1.0｜原生下載接手調整

- 調整網站原生檔案的接手與傳送流程，嘗試減少逐張存檔確認。
- 使用者測試仍出現逐張另存提示，後續於 1.2.0 改採資料夾直存。

### 1.0.0｜初始版本

- 支援 Tensor.Art 與 Tensorhub.Art 單篇多圖，依序操作網站原生下載按鈕。
- 提供下載進度、暫停／停止與另外保存貼文資料 JSON 的選項。

## 驗證紀錄

截至 2026-10-27，1.2.2 已通過 43 項自動化測試，並獲使用者回報整體運作正常，包含本次修正的作者下載流程。這是實際使用回饋，不代表所有 Chromium 瀏覽器、帳號與網站情境皆已測試。

自動化測試涵蓋：

- 兩站來源傳遞、作者模式辨識、來源失敗阻擋、重新連接與切換作者清單清除。
- 原檔位元組與內嵌生成參數保留、每站九張連續檔案流程，以及不同原生儲存路徑。
- 實際磁碟寫入與讀回、傳輸與存檔後 SHA-256 核對、資料損壞時阻止存檔。
- 資料夾記憶與授權恢復、重複層級防護、既有檔案核對續抓與同名不覆蓋。
- 作者貼文去重與逐篇展開。

自動化測試的瀏覽器訊息與資料夾控制代碼採用模擬或轉接實作，檔案則實際寫入／讀回磁碟；開發環境未執行完整 Windows Chrome 端到端測試，也未自動操作作業系統的資料夾選擇視窗。網站結構、登入狀態與瀏覽器權限變動仍可能影響使用。

原始碼及測試包含於本包。開發者可執行：

```sh
node --test tests/test-*.cjs
```
